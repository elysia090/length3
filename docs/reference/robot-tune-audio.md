末尾の 0.5 拍休みと、次のフレーズ頭への接続は未検証。

## 切り出し基準と未検証事項

基準は冒頭 0〜3 秒のフレーズと、その後に音が重なった同じフレーズ。
短いアタック間隔だけでなく、周波数帯別の包絡の並びを冒頭と後半で照合した。
パターンの反復候補は約 2.8911041666666666 秒（138,773 フレーム）で、
その 2 回分に相当する波形の再帰間隔は約 5.782208333333333 秒だった。
継ぎ目のサンプル値と傾きを合わせるため、入口を数 ms の範囲で探し、
終点を再帰間隔から 12 フレーム（0.25 ms）短く微調整した。

これは信号の相関から得た候補であり、拍数や音楽上のフレーズ区分の確定値ではない。
切り出し区間内の休みはすべて反復時間に含まれる。休みを別に追加した処理はない。
ただし、ユーザーが指摘した**末尾の 0.5 拍休み**を独立に特定できていないため、
「発音する本体 → 末尾 0.5 拍休み → 同じフレーズの頭」の接続が成立するかは未検証。
発音部分の長さと休符を分けて確認し、戻りで休みが延びたり重複したりしないかを調べる。
PCM の一致とフレーム数は確認済みだが、聴感で自然なループであるとは確定していない。

以前 push した 13.089479166666667〜17.248125 秒の切り出し（約 4.159 秒）は、
ユーザーの試聴で戻りのリズムが跳ぶと指摘されたため撤回し、今回の WAV で置き換えた。
続く約 4.336 秒の確認版も、冒頭のフレーズ全体との対応を確認せず周期だけ合わせた候補で、
現在の WAV には使っていない。

## 13 拍という前提の訂正

旧実装はループ長を先に 13 で割り、そこから約 166.03 BPM を逆算している。
その拍の長さを再びループ長に当てて「ちょうど 13 拍」とするのは循環であり、
音源の拍数の検証にならない。13 拍の前提は撤回し、旧版・新版のどちらについても
測定で裏付けられた事実として扱わない。イントロ 33 拍も同様に未確定。

WAV の長さだけを再生成しても、13 拍の定数は残る。
そこから逆算される BPM は音源のテンポを測定した結果ではない。
先に発音部分と末尾休符、フレーズの反復、アタックの間隔、入口と終点の拍節上の位置を
確認し、その結果から時刻表と振付を決める。13 拍・33 拍や 26 個の振付を保つために
音源を加工したり、テンポを逆算して正当化したりしない。

## 追従作業の手順

1. 冒頭 0〜3 秒と後半のフレーズを聴き比べ、発音する本体と末尾 0.5 拍休みを
   区別する。入口・終点と休符の扱いを決め、複数周で自然に戻ることを確認する。
2. リポジトリの Node 24 環境で、`libmp3lame` が使える `ffmpeg` を PATH に置き、
   次のコマンドで MP3 と包絡を一緒に再生成する。

   ```sh
   node ./scripts/robot-tune/bake.ts
   ```

3. 生成された秒数、オンセット、包絡、無音区間に加え、音源で測った周期と拍の位置から
   時刻表を決める。その後に振付・テスト・記事を追従させる。
4. `pnpm check` と `pnpm test:unit` を実行し、ブラウザでもイントロからの接続と
   複数周の再生、無音と動きの同期を確認する。

再生成スクリプトは [bake.ts](../../scripts/robot-tune/bake.ts)。通常のサイトビルドで
自動実行される処理ではないため、WAV の差し替えだけでは配信音声は変わらない。
