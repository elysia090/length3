# Robot Tune 音源と追従状況

更新日: 2026-10-07

`data/` の clean なイントロとループを切り直した。配信用 MP3、生成済み包絡、
拍の時刻表、振付、テスト、記事は旧音源のままで、今回の更新では追従していない。
サイトの再生音は `data/` の WAV を直接読まず、`public/audio/robot-tune.mp3` を使う。

## 現在の WAV

音源: [French Class — Robot Tune](https://www.youtube.com/watch?v=a1rjVVcZvTY)。
秒数はダウンロードした音声の復号後の先頭を基準とする。
両ファイルとも 48,000 Hz、ステレオ、24-bit PCM WAV。

| ファイル | 元音源の区間（秒、終点は含まない） | フレーム数 | 長さ（秒） |
| --- | --- | ---: | ---: |
| [robot_tune_intro.wav](../../data/robot_tune_intro.wav) | 0 → 13.089479166666667 | 628,295 | 13.089479166666667 |
| [robot_tune_loop.wav](../../data/robot_tune_loop.wav) | 13.089479166666667 → 17.248125 | 199,615 | 4.158645833333333 |

48 kHz のフレーム番号ではイントロが `[0, 628295)`、ループが
`[628295, 827910)`。イントロから最初のループへは重複も欠落もなく接続する。
ループの `smpl` チャンクはファイル全体を指定し、開始フレームは 0、
終了フレームは 199,614（このメタデータでは終点を含む）。

終点は 17.000 秒に固定せず、次の音が始まる直前に置いた。
波形から検出した次のアタックは約 17.252292 秒で、切り出し終点はその
200 フレーム、約 4.167 ms 前にある。入口も約 13.093479 秒のアタックより
192 フレーム、4 ms 前から始めている。このアタック検出値と、配信用スクリプトの
閾値で求める `LOOP_ONSET_SEC` は別の値なので、そのまま転記しない。

追加音源とのミックス、音量変更、タイムストレッチ、EQ、コンプ、リバーブは加えていない。
ループ末尾の 48 フレーム（1 ms）だけ、最後のサンプルをループ先頭に合わせる
微小な端点補正を行った。イントロと、それ以外のループ部分は元の復号 PCM を
24-bit に量子化したもの。波形とフレーム数は確認済みだが、聴感での自然さは未確認。

## 未追従の箇所

旧版のイントロは 12.248708333333333 秒、ループは 4.697875 秒で、
元音源の終点は 16.946583333333333 秒だった。以下は引き続きこの旧版を前提にする。

WAV の長さだけを再生成すると、13 拍の定数は残り、計算上のテンポが約
187.56 BPM に変わる。これは新しい音源のテンポを測定した値ではない。
新ループの拍数は未確定なので、13 拍や 33 拍を保つために音源を加工せず、
アタックと周期を測り直してから時刻表と振付を決める。

## 追従作業の手順

1. 新しい WAV を聴き、入口・終点と周回の自然さを確認する。
2. リポジトリの Node 24 環境で、`libmp3lame` が使える `ffmpeg` を PATH に置き、
   次のコマンドで MP3 と包絡を一緒に再生成する。

   ```sh
   node ./scripts/robot-tune/bake.ts
   ```

3. 生成された秒数、オンセット、包絡、無音区間を基準に、拍数・振付・テスト・記事を追従させる。
4. `pnpm check` と `pnpm test:unit` を実行し、ブラウザでもイントロからの接続と
   複数周の再生、無音と動きの同期を確認する。

再生成スクリプトは [bake.ts](../../scripts/robot-tune/bake.ts)。通常のサイトビルドで
自動実行される処理ではないため、WAV の差し替えだけでは配信音声は変わらない。
