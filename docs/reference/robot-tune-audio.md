## 現在の WAV

音源: [French Class — Robot Tune](https://www.youtube.com/watch?v=a1rjVVcZvTY)。

両ファイルとも 48,000 Hz、ステレオ、24-bit PCM WAV。

48 kHz のフレーム番号ではイントロが `[0, 628295)`、ループが
`[628295, 827910)`。イントロから最初のループへは重複も欠落もなく接続する。
ループの `smpl` チャンクはファイル全体を指定し、開始フレームは 0、
終了フレームは 199,614（このメタデータでは終点を含む）。

終点は 17.000 秒に固定せず、次の音が始まる直前に置いた。
波形から検出した次のアタックは約 17.252292 秒で、切り出し終点はその
200 フレーム、約 4.167 ms 前にある。入口も約 13.093479 秒のアタックより
192 フレーム、4 ms 前から始めている。このアタック検出値と、配信用スクリプトの
閾値で求める `LOOP_ONSET_SEC` は別の値なので、そのまま転記しない。

追加音源とのミックス、音量変更、タイムストレッチ、EQ、コンプ、リバーブは加えていない。
ループ末尾の 48 フレーム（1 ms）だけ、最後のサンプルをループ先頭に合わせる
微小な端点補正を行った。イントロと、それ以外のループ部分は元の復号 PCM を
24-bit に量子化したもの。波形とフレーム数は確認済みだが、聴感での自然さは未確認。

## 未追従の箇所

旧版のイントロは 12.248708333333333 秒、ループは 4.697875 秒で、
元音源の終## 追従の結果

`node ./scripts/robot-tune/bake.ts` が MP3 と `envelope.ts` を作り直し、拍も音から測る。

| 量                                      | 値                                  | 測り方                                                                                        |
| --------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------- |
| 8 分音符の周期                          | 約 0.181 s（約 166 BPM）            | 低域＋高域の RMS の対数の増分（5 ms 刻み）を、ループ 4 周ぶんの自己相関で探す（0.15〜0.22 s） |
| ループの 8 分音符の数 `LOOP_EIGHTHS`    | 23（11 拍半）                       | ループ長 / 周期 = 23.03 を丸める                                                              |
| `EIGHTH_SEC`                            | 0.18081 s                           | ループ長 / 23。周回でずれが積もらない                                                         |
| イントロの 8 分音符の数 `INTRO_EIGHTHS` | 70（35 拍）                         | 最初の立ち上がり（0.45 s）からループ頭まで / `EIGHTH_SEC`                                     |
| `LOOP_ACCENTS`                          | 8 分音符ごとの低域の立ち上がり 0..1 | 各 8 分音符の ±25 ms の最大値                                                                 |

別途の解析（オンセットの山を 8 分音符の格子に当てはめる）でも、周期 0.18056 s、
ループ長 / 周期 = 23.03、イントロの強いオンセットの残差 ±8 ms 以内で、同じ結論になった。

振付（`choreo.ts`）はこの値から組む。ループでいちばん強いキック（12 番目）と二番目
（18 番目）に、2³ の殻 7 個と 3³ の殻 19 個の一掬いを着地させる。テストは
「ループ長が測った 8 分音符の整数倍であること」「着地が強いキックの上位 3 つに
あること」を見ていて、特定のテンポや拍数を決め打ちしていない。

拍の長さを再びループ長に当てて「ちょうど 13 拍」とするのは循環であり、
音源の拍数の検証にならない。13 拍の前提は撤回し、旧版・新版のどちらについても
測定で裏付けられた事実として扱わない。イントロ 33 拍も同様に未確定。

WAV の長さだけを再生成すると、13 拍の定数は残り、計算上は約 187.56 BPM になる。
この値も音源のテンポを測定した結果ではない。先にアタックの間隔、包絡、周期、
入口と終点の拍節上の位置を調べ、時間で切った区間が整数拍に相当するかも確認する。
その結果から時刻表と振付を決める。13 拍・33 拍や 26 個の振付を保つために
音源を加工したり、テンポを逆算して正当化したりしない。

## 音源を差し替えたとき

1. `node ./scripts/robot-tune/bake.ts`（`libmp3lame` が使える `ffmpeg` が必要）。
2. 生成された `LOOP_EIGHTHS`・`LOOP_ACCENTS` を見て、`choreo.ts` の `LOOP_THROWS`
   （掬う・放る・着地の 8 分音符）が強いキックに乗っているか確かめる。テストが
   外れを知らせる。
3. `pnpm check` と `pnpm test:unit`、ブラウザでイントロからの接続と複数周の再生を確認する。
